# 概要要件定義書（ドラフト）
## マルコフ連鎖を用いた株価・FX 時系列予測システム

> 本書は提供されたリサーチ資料（YouTube 知識ノート「The Hedge Fund Method: Markov Chain Approach」の要約シャード）を根拠とした**概要レベル**の要件定義である。詳細設計に進む前に、第10章「未決事項」を関係者間で合意する必要がある。

---

## 第1章 概要と目的

- **目的:** EMA・RSI などの単純指標に依存する一般的なトレード手法とは異なり、ヘッジファンドが用いる客観的・確率的な「マルコフ連鎖アプローチ」で市場を分析し、**翌日（短期）の市場方向性**を確率として提示するフレームワークを構築する。
- **ねらい:** 人間の直感・主観的な「市場感覚」を数値化し、再現可能で客観的な確率シグナルへ変換する。
- **適用範囲:** 資産種別に依存しない汎用フレームワーク（暗号資産=BTC、株式指数=SPY、個別株=TSLA 等。FX への適用も想定）。

## 第2章 スコープ

| 区分 | 内容 |
| --- | --- |
| In Scope | 状態ラベリング、遷移行列の構築、多日間予測（行列累乗）、シグナル生成、ポジションサイズ算出、バックテスト、可視化 |
| Out of Scope（現時点） | 自動発注・約定執行、ブローカー API 連携、本番資金での自動売買（※未決事項で要判断） |

## 第3章 用語定義

| 用語 | 定義 |
| --- | --- |
| マルコフ性 | 次状態が過去の履歴に依らず**現在の状態のみ**で決まる性質 |
| 状態（レジーム） | Bull（上昇）/ Bear（下落）/ Sideways（横ばい）の3区分 |
| 遷移行列 P | 状態 i から j への遷移確率を並べた行列（各行の和=100%） |
| スティッキネス | 遷移行列の対角成分。レジームの持続性（トレンドの強さ）を示す |
| 定常分布 | 行列累乗を繰り返した際に収束する均衡確率分布 |
| ウォークフォワード検証 | 期間ごとにモデルを再計算し、データ漏洩を防ぐ逐次バックテスト手法 |

## 第4章 機能要件

### 4.1 状態定義・ラベリング
- 過去 **20 日間の累積リターン**に基づき各日を分類する。
  - Bull: **+5% 以上** / Bear: **−5% 以下** / Sideways: その間
- ラベリングは 20 日分のデータが揃う時点（20日目）から開始し、全履歴に適用して客観的な状態時系列を構築する。

### 4.2 遷移行列の構築
- 状態 i から j への遷移回数 `N(i→j)` をカウントし、状態 i の総観測回数で割って遷移確率を得る。
- 各行の合計が 100% になる「予測確率グリッド」を生成する。
- 対角成分からスティッキネス（持続性）スコアを算出する。

### 4.3 多日間予測
- N 日先の予測は遷移行列の累乗（P², P³ …）で算出する。
- **制約:** 長期（例 28 日）では定常分布に収束し確率が均一化、シグナル価値を失うため、**短期（1〜数日）予測に焦点**を当てる。

### 4.4 シグナル生成
- 差分 = `P(翌日Bull) − P(翌日Bear)` を算出。
  - 符号が正 → ロング、負 → ショート。
  - 絶対値の大きさ → ポジションサイズ（例: Bull65%−Bear20%=+45% → 強いロング）。
- シグナル発火の閾値（中立帯）を設定可能とする。

### 4.5 可視化・統合
- TradingView Pine Script による遷移行列／レジームのチャート可視化。
- AI 環境での `/markov` コマンド呼び出しによりワークフローへ統合（LLM スキル `markov-hedge-fund-method` / `markov-regime`）。

## 第5章 データ要件
- 入力: 対象資産の日足 OHLC（最低でも 20 日 + 学習に十分な履歴）。
- 累積リターン算出のための連続した時系列。
- データ漏洩防止のため、学習区間と検証区間を厳密に分離する。

## 第6章 非機能要件
- **再現性:** 同一入力・同一パラメータで同一結果を返す。
- **汎用性:** 資産非依存（パラメータ差し替えで多資産対応）。
- **客観性:** 主観を排したアルゴリズム的ラベリング。
- **保守性:** 状態定義・閾値・予測ウィンドウをパラメータ化。

## 第7章 システム構成（概要）
1. データ取得層（日足取得）
2. ラベリング層（状態時系列生成）
3. モデル層（遷移行列構築・行列累乗）
4. シグナル層（差分・ポジションサイズ算出）
5. 検証層（ウォークフォワードバックテスト）
6. 出力層（Pine Script 可視化 / `/markov` 連携）

## 第8章 検証・リスク管理要件
- **必須:** ウォークフォワードバックテスト（期間ごとにモデル再計算）でデータ漏洩を防止。
- **代替案:** 主観的ラベルを排除する隠れマルコフモデル（HMM）の採用可否を評価。
- リスク: 定常分布収束による長期シグナル無効化、レジーム急変時の遷移確率の陳腐化。

## 第9章 運用・保守
- モデル再計算（更新）頻度の規定。
- 監視項目（シグナル分布の異常、スティッキネスの急変）。
- パラメータ調整フローと異常時の対応プロトコル。

## 第10章 未決事項（要・関係者合意 / grill 継続対象）

| # | 論点 | 推奨（暫定） |
| --- | --- | --- |
| 1 | 予測の最終出力（方向確率 / 売買シグナル / 自動発注まで） | まず**方向の確率＋差分シグナル**を出力。自動発注は別フェーズ |
| 2 | 対象市場（株 / FX / 暗号資産）と時間軸（日足固定か） | 日足・単一資産で MVP → 後に多資産・他時間軸へ拡張 |
| 3 | 状態数（3状態固定か、ボラ等の軸を追加するか） | まず3状態（Bull/Bear/Sideways）で確立 |
| 4 | 状態定義の閾値（±5%・20日窓は資産共通か、資産別最適化か） | 既定値±5%/20日で開始、資産別チューニングは検証で判断 |
| 5 | FX 特有の扱い（24時間市場・通貨ペア・スプレッド） | FX 適用時に「日足の区切り」「取引コスト」を別途定義 |
| 6 | ラベリング方式（ルールベース or HMM） | ルールベースで MVP、HMM は精度比較の実験として |
| 7 | 評価指標（的中率 / 期待値 / シャープレシオ / 最大DD） | バックテストで複数指標を併用、主指標は要合意 |
| 8 | 実装スタック（Python / Pine Script / LLM スキルの責務分担） | 計算=Python、可視化=Pine Script、対話=LLM スキル |
