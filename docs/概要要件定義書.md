# 概要要件定義書（ドラフト）
## マルコフ連鎖を用いた FX 時系列予測システム（MT5 / MQL5）

> 本書は提供されたリサーチ資料（YouTube 知識ノート「The Hedge Fund Method: Markov Chain Approach」の要約シャード）を出発点とし、関係者との合意（grill）で確定した MVP 方針を反映した**概要レベル**の要件定義である。素材は株/暗号資産・日足・固定±5% を前提としていたが、本 MVP は **FX 複数通貨ペア / MT5・MQL5** を対象とするため、状態定義・実装環境を改訂している。詳細設計に進む前に、第10章「未決事項」を関係者間で合意する必要がある。

---

## 第1章 概要と目的

- **目的:** EMA・RSI などの単純指標に依存する一般的なトレード手法とは異なり、ヘッジファンドが用いる客観的・確率的な「マルコフ連鎖アプローチ」で市場を分析し、**翌日（短期）の市場方向性**を確率として提示するフレームワークを構築する。
- **ねらい:** 人間の直感・主観的な「市場感覚」を数値化し、再現可能で客観的な確率シグナルへ変換する。
- **MVP 対象:** **FX（複数通貨ペアを同時に扱う）**。タイムフレームは **MVP 既定=日足**とし、外部パラメータで可変とする（第4.6章）。
- **将来拡張:** 本フレームワーク自体は資産非依存に設計し、将来的に株式指数・個別株・暗号資産（SPY / TSLA / BTC 等）へ拡張可能とする。

## 第3章 用語定義

| 用語 | 定義 |
| --- | --- |
| マルコフ性 | 次状態が過去の履歴に依らず**現在の状態のみ**で決まる性質 |
| 状態（レジーム） | Bull（上昇）/ Bear（下落）/ Sideways（横ばい）の3区分 |
| 遷移行列 P | 状態 i から j への遷移確率を並べた行列（各行の和=100%） |
| スティッキネス | 遷移行列の対角成分。レジームの持続性（トレンドの強さ）を示す |
| 定常分布 | 行列累乗を繰り返した際に収束する均衡確率分布 |
| z スコア | 累積リターンを自ペアのローリング標準偏差で標準化した値 |
| ウォークフォワード検証 | 期間ごとにモデルを再計算し、データ漏洩を防ぐ逐次バックテスト手法 |
| `input`（外部パラメータ） | MQL5 でストラテジーテスターから指定・最適化できる設定値 |

## 第4章 機能要件

### 4.1 状態定義・ラベリング（ボラ正規化 / z スコア型）
- 各ペアの **累積リターン窓（既定 20 本）** のリターンを、**自ペアのローリング標準偏差で標準化（z 値化）** する。
- 共通の **σ 閾値（暫定 ±0.5σ）** で分類する。
  - Bull: z ≥ +閾値 / Bear: z ≤ −閾値 / Sideways: その間
- 固定 ±5% は採用しない（FX メジャー通貨ではボラが小さく、ほぼ全て Sideways に偏るため）。z スコア型なら**単一の閾値設定で全ペアへ公平に適用**でき、ペア固有のボラ差を吸収しつつ「トレンドの強さ」の意味を保つ。
- 窓長が揃う時点からラベリングを開始し、対象期間の全履歴に適用して客観的な状態時系列を構築する。
- 累積リターン窓長・標準偏差窓長・σ 閾値はすべて外部パラメータ（第4.6章）。

### 4.2 遷移行列の構築
- **通貨ペアごとに独立した遷移行列 P を学習する**（全ペアをプールした単一モデルは採用しない）。ペア固有の遷移挙動を捉えるため。
- 状態 i から j への遷移回数 `N(i→j)` をカウントし、状態 i の総観測回数で割って遷移確率を得る。
- 各行の合計が 100% になる「予測確率グリッド」を生成する。
- 対角成分からスティッキネス（持続性）スコアを算出する。

### 4.3 多日間予測
- N 日先の予測は遷移行列の累乗（P², P³ …）で算出する。
- **制約:** 長期（例 28 日）では定常分布に収束し確率が均一化、シグナル価値を失うため、**短期（1〜数日）予測に焦点**を当てる。予測ステップ数 N は外部パラメータ。

### 4.4 シグナル生成・ポジション決定
- 差分 = `P(翌日Bull) − P(翌日Bear)` を算出。
  - 符号が正 → ロング、負 → ショート。
  - 絶対値の大きさ → シグナル強度（例: Bull65%−Bear20%=+45% → 強いロング）。
- シグナル発火の閾値（中立帯）を外部パラメータで設定可能とする。
- **取引量は固定ロットではなく、投資可能残高に対する % 割合で算出する。**
  - リスク % ベースのロット計算（残高 × 指定% を基準に、差分強度に応じてスケール）。
  - 既定リスク%・最大%・1トレード上限を外部パラメータ化する。

### 4.5 FX 固有要件
- 24 時間市場のため「1営業日（日足）」の区切り＝クローズ基準の定義が必要（暫定 NY クローズ基準、具体時刻は未決）。
- スプレッド／取引コストをバックテスト評価に含める。
- pip 建て・通貨ペア単位での独立処理。
- データ供給元は MT5（ブローカー配信のヒストリカルデータ、`CopyRates` 等）を前提とする。

### 4.6 外部パラメータ設計（MT5 `input`）
- モデル・状態定義・ポジション管理の各値を MQL5 の `input` として公開し、**MT5 ストラテジーテスターで指定・最適化**できるようにする。
- 主なパラメータ（暫定）:
  - 対象通貨ペア（シンボル）、**タイムフレーム**（MVP 既定=日足、`input` で可変）。
  - 累積リターン窓長（既定 20）、z スコア標準偏差の窓長、状態判定の σ 閾値。
  - 予測ステップ数 N（行列累乗の次数）、シグナル発火の差分閾値（中立帯）。
  - 投資可能残高に対するリスク %、最大% / 1トレード上限。

## 第5章 データ要件
- 入力: 対象通貨ペアの OHLC（タイムフレームは `input`、MVP 既定=日足）。最低でも「累積リターン窓 + 標準偏差窓 + 学習に十分な履歴」が必要。
- 複数ペア分を、クローズ基準を揃えて取得する。
- データ漏洩防止のため、ペアごとに学習区間と検証区間を厳密に分離する。

## 第6章 非機能要件
- **再現性:** 同一入力・同一パラメータで同一結果を返す。
- **汎用性:** 資産非依存（パラメータ差し替えで多通貨ペア／将来は多資産対応）。
- **客観性:** 主観を排したアルゴリズム的ラベリング（z スコア型）。
- **保守性:** 状態定義・閾値・予測ウィンドウ・ポジション設定をすべて `input` 化。

## 第7章 システム構成（概要）
1. データ取得層（MT5 から OHLC 取得、`CopyRates` 等）
2. ラベリング層（z スコアによる状態時系列生成）
3. モデル層（ペア別遷移行列の構築・行列累乗）
4. シグナル層（差分算出・残高%ベースのポジションサイズ算出）
5. 検証層（MT5 ストラテジーテスター上のウォークフォワードバックテスト）
6. 出力/実行層（MT5 カスタムインジケーターによる可視化、EA による発注ロジック）

## 第8章 実装環境とツール統合
- **実装/稼働環境: MetaTrader 5（MT5）。開発言語: MQL5。**
  - ラベリング・遷移行列・行列累乗・シグナル算出を MQL5 で実装（行列演算は MQL5 の matrix 型／自前実装で対応）。
  - 可視化は MT5 **カスタムインジケーター**、売買ロジックは **EA（Expert Advisor）** に切り分ける方針（責務分担の詳細は実装フェーズ）。
- 素材記載の TradingView Pine Script は「参考実装」に格下げ（本 MVP の対象外）。
- LLM スキル（`/markov` 等）は分析補助の任意ツールとして残置。

## 第9章 検証・リスク管理要件
- **必須:** ウォークフォワードバックテスト（期間ごとにモデル再計算）でデータ漏洩を防止。MT5 ストラテジーテスターで実施。
- スプレッド／取引コストを反映した評価とする。
- **代替案:** 主観的ラベルを排除する隠れマルコフモデル（HMM）の採用可否を将来評価。
- リスク: 定常分布収束による長期シグナル無効化、レジーム急変時の遷移確率の陳腐化、ペアごとの履歴量不足による遷移確率の不安定化。

## 第10章 運用・保守
- モデル再計算（更新）頻度の規定。
- 監視項目（シグナル分布の異常、スティッキネスの急変）。
- パラメータ調整フローと異常シグナル発生時の対応プロトコル。
