# 詳細設計書（ドラフト）
## マルコフ連鎖 FX 予測システム（MT5 / MQL5）

> 本書は `docs/概要要件定義書.md`（確定13項目）を実装可能なレベルへ落とした詳細設計である。MQL5（ビルド 3000 以降の `matrix`/`vector` 型を前提）で実装することを想定する。末尾「第12章 新規決定点」に、詳細設計で初めて顕在化した未確定事項を推奨付きで列挙する。

---

## 第1章 設計方針・前提
- 言語: MQL5。行列演算は標準の `matrix`/`vector` 型を用いる。
- 計算ロジックは共通インクルード `.mqh` に集約し、インジケーターと EA から共有する（要件 #12）。
- 1 インスタンス＝1 シンボル（通貨ペア）を担当し、自シンボルの履歴のみから独立した遷移行列を学習する（要件 #5）。複数ペアは「シンボルごとにインスタンスを動かす」ことで実現する（第10章）。
- すべての判断は**確定足（closed bar）**で行い、未来情報を参照しない（要件: データ漏洩防止）。
- タイムフレームは `input`（既定 PERIOD_D1）。日足境界は MT5 サーバー時刻＝NY クローズ基準（17:00 ET）に整合している前提（要件 #13）。

## 第3章 データ構造（MarkovTypes.mqh）

```mql5
// 市場状態（3 状態：要件 #3）。行列の添字としても使う。
enum ENUM_REGIME { REGIME_BEAR = 0, REGIME_SIDE = 1, REGIME_BULL = 2 };
#define REGIME_COUNT 3

// エントリーモード（D-5 確定：input で選択可能）
enum ENUM_ENTRY_MODE
{
   ENTRY_SINGLE,           // 1ポジションのみ。保有中は新規エントリーしない
   ENTRY_REVERSAL,         // 反対シグナルで決済して即ドテン（反転）
   ENTRY_PYRAMID,          // 同方向シグナル継続で上限まで積み増し
   ENTRY_SCALE_BY_STRENGTH // 差分強度に応じて分割エントリー
};

// 1 本の予測結果
struct MarkovForecast
{
   double prob[REGIME_COUNT];   // 各状態の確率（行ベクトル、和=1）
   double diff;                 // P(Bull) - P(Bear)
   int    signalDir;            // +1=Long, -1=Short, 0=中立
   double stickiness[REGIME_COUNT]; // 対角成分（持続性）
};
```
- 遷移行列は `matrix`（3×3）で保持。行 i = 現状態、列 j = 次状態、各行の和 = 1。

## 第4章 共通ライブラリのインターフェース（MarkovEngine.mqh）

```mql5
class CMarkovEngine
{
public:
   // パラメータ注入（input から渡す）
   void Configure(int retWindow, int stdWindow, double sigmaThreshold,
                  int trainLookback, bool expandingWindow, int forecastSteps,
                  double diffThreshold, double laplaceAlpha);   // R3: 追加

   // 確定足インデックス shift（1=直近確定足）時点で、過去のみを使って予測を生成
   bool BuildForecast(const string symbol, ENUM_TIMEFRAMES tf,
                      int shift, MarkovForecast &out);
};
```
- 内部で Labeler → Matrix → 累乗 → Signal の順に呼ぶ。
- `shift` 起点で過去データのみ参照することで、バー単位のウォークフォワードを自然に満たす。

## 第5章 アルゴリズム詳細（擬似コード）

### 5.1 累積リターンと z スコア（MarkovLabeler）
```
# bar t の状態を決める（t は確定足）
r_t = log(Close[t] / Close[t - retWindow])          # retWindow 本の累積対数リターン
# 直近 stdWindow 本の累積リターン系列 {r} の標準偏差で標準化
sigma = stddev( r[t-stdWindow+1 .. t] )
z_t = (sigma > 0) ? r_t / sigma : 0
```

### 5.2 状態ラベリング
```
if   z_t >= +sigmaThreshold : label = REGIME_BULL
elif z_t <= -sigmaThreshold : label = REGIME_BEAR
else                        : label = REGIME_SIDE
```
- ウォームアップ: 先頭 `retWindow + stdWindow` 本はラベル不能 → スキップ。

### 5.3 遷移行列の構築（MarkovMatrix）
```
N = zero(3,3)
for k in 学習区間の各確定足:
    i = label[k]; j = label[k+1]      # k+1 も確定足のみ
    N[i][j] += 1
# 行正規化（行和で割る）。行和=0 の行は一様分布で埋める（後述ラプラス平滑化も可）
for i in 0..2:
    rowsum = sum(N[i])
    P[i] = (rowsum>0) ? N[i]/rowsum : (1/3,1/3,1/3)
```
- 学習区間は `trainLookback` 本（`expandingWindow=true` なら利用可能な全履歴）。
- ゼロ頻度対策に**ラプラス平滑化（各カウントに +α）**をオプション化（第12章 D-3）。

### 5.4 多ステップ予測（行列累乗）
```
Pn = P^forecastSteps                  # MQL5 matrix の乗算で実装
current = onehot(label[直近確定足])    # 現状態の行ベクトル
probVec = current * Pn                # 予測確率分布
```
- `forecastSteps` は短期（1〜数本）。長期は定常分布に収束しシグナル価値を失う（要件 4.3）。
- **Y5: `forecastSteps` は「予測確率分布の地平（何本先の分布を見るか）」であり、エントリー判断自体は毎確定足で行う。** 保有期間は手仕舞いルール（D-4: 反対シグナル／`InpExitBars`／TP・SL）で決まり、`forecastSteps` とは独立。

### 5.5 差分シグナル（MarkovSignal）
```
diff = probVec[BULL] - probVec[BEAR]
if   diff >=  diffThreshold : signalDir = +1   # Long
elif diff <= -diffThreshold : signalDir = -1   # Short
else                        : signalDir = 0    # 中立帯
```

### 5.6 残高%ベースのロット計算（MarkovSizing）
```
# リスク割合を差分強度でスケール（要件 #9）
strength   = clamp(|diff|, 0, 1)
riskFrac   = baseRiskPct + (maxRiskPct - baseRiskPct) * strength   # %→比率
riskAmount = equity * riskFrac                 # Y4: equity = AccountInfoDouble(ACCOUNT_EQUITY)
# 損切り距離 = ATR ベースの動的 SL（D-1 確定）
atr        = CopyBuffer(atrHandle, 0, shift, 1)   # Y2: iATR はハンドル→CopyBuffer で値取得
slDistance = InpAtrSLMult * atr            # 価格距離（例 1.5×ATR）
tickSize   = SymbolInfoDouble(symbol, SYMBOL_TRADE_TICK_SIZE)
tickValue  = SymbolInfoDouble(symbol, SYMBOL_TRADE_TICK_VALUE)  # Y3: 口座通貨建て・ペア依存
slValue    = slDistance / tickSize * tickValue   # 1 ロットあたりの損切り金額（口座通貨）
lots       = riskAmount / slValue
lots       = NormalizeLots(symbol, lots)   # MinLot/LotStep/MaxLot に丸め
```
- **Y4: 「投資可能残高%」は口座 equity（`ACCOUNT_EQUITY`）基準とする**（要件 #9 の解釈を確定）。
- **Y2: `iATR` 等の MQL5 テクニカル関数はハンドルを返す。** `OnInit` で `atrHandle = iATR(...)` を一度生成し、`CopyBuffer` で値を取得する。
- **Y3: `SYMBOL_TRADE_TICK_VALUE` は口座通貨建てでペア・ブローカーに依存。** クロス円・クロス通貨では換算が含まれる点に留意（複数ペア横断時の前提）。

## 第7章 インジケーター設計（MarkovRegime.mq5）
- `OnCalculate` で確定足ごとに `CMarkovEngine::BuildForecast` を呼ぶ。
- **Y2: 新規バーガード必須。** `OnCalculate` は毎ティック呼ばれるため、`prev_calculated` とバー時刻で新規確定足のときだけ再計算する（毎ティックで全履歴の行列再計算をすると過負荷）。
- 表示: 状態色分け（背景/サブウィンドウ）、P(Bull)/P(Bear)/diff のライン、スティッキネス値のラベル。
- 描画のみ。発注は行わない。

## 第8章 EA 設計（MarkovBacktestEA.mq5）
- `OnInit`: input を `CMarkovEngine::Configure` に注入。
- `OnTick`: **新規バー確定検出**（`iTime(_Symbol,InpTimeframe,0)` の変化）時のみ処理。
- エントリー挙動は `InpEntryMode`（`ENUM_ENTRY_MODE`、D-5 確定）で分岐：
  ```
  if 新規バー確定:
      engine.BuildForecast(_Symbol, InpTimeframe, 1, fc)   # shift=1=直近確定足

      switch InpEntryMode:
        ENTRY_SINGLE:
            if ノーポジ and fc.signalDir != 0: OpenPosition(fc)
            # 既存手仕舞いは D-4（反対シグナル or N本経過 or TP/SL）
        ENTRY_REVERSAL:
            if 保有方向 == -fc.signalDir: ClosePosition(); OpenPosition(fc)  # ドテン
            elif ノーポジ and fc.signalDir != 0: OpenPosition(fc)
        ENTRY_PYRAMID:
            if 同方向シグナル継続 and ポジション数 < InpMaxPyramid: AddPosition(fc)
            elif ノーポジ and fc.signalDir != 0: OpenPosition(fc)
        ENTRY_SCALE_BY_STRENGTH:
            目標ロット = sizing(fc.diff)（強度比例）
            現ロットとの差分だけ分割で増減（上限 InpMaxPyramid 分割）
  ```
- 各モード共通で、発注は成行＋ATR ベース SL／TP（D-1, D-4）。手仕舞いは D-4（反対シグナル or N 本経過）。
- ストラテジーテスターでの最適化対象は input 群（第6章）。

## 第9章 ウォークフォワード/テスター構成
- バー単位処理が `shift` 起点の過去のみ参照のため、**テスター実行が自然にウォークフォワード**になる（各バーでその時点までの履歴から行列を再計算）。
- 明示的な期間分割最適化（前進検証）は MT5 テスターの「フォワードテスト」機能を併用。
- スプレッド／取引コストはテスター設定（実スプレッド or カスタム）で反映（要件 第9章）。

## 第10章 マルチシンボルの扱い
- 各ペア独立（要件 #5）のため、**1 インスタンス＝1 シンボル**を基本とする（D-2 確定）。
- MT5 の制約: ストラテジーテスターの最適化は 1 実行 1 シンボルで、テスター対象シンボルを MQL5 から変更できない。よって「シンボル別の最適パラメータ」を得るにはシンボルごとに最適化を回す必要がある。
- これを手動のシンボル切替なしで自動化するため、**第14章「マルチシンボル最適化オーケストレーション（3層構成）」**を採用する。

## 第11章 エラー処理・境界条件
- 履歴不足（`Bars < retWindow+stdWindow+trainLookback`）時は予測スキップ・発注なし。
- `sigma=0`（無変動）時は z=0 → SIDE。
- 行和 0 の行は一様分布（またはラプラス平滑化）で埋める。
- ロットは `SYMBOL_VOLUME_MIN/STEP/MAX` で正規化、証拠金不足チェック。

## 第13章 テスト方針
- `.mqh` 単体: 既知の小データで z スコア・行列・累乗・差分の値を検証（テスト用スクリプトで assert）。
- 行列累乗の検証: 行和=1 の保存、`P^1` が `P` に一致。
- EA 結合: テスターで短期間を実行し、発注が確定足のみ・未来参照なしであることをログで確認。

## 第14章 マルチシンボル最適化オーケストレーション（3層構成・D-2 確定）

目的: ユーザーがシンボルを手動で切り替えながらシミュレーションしなくても、**全シンボルの最適化を連続実行し、シンボル別に最適パラメータセットを自動選定**し、最後に一括で検証できるようにする。

### 14.1 ① EA 側：複合スコア算出と SQLite への試行データ記録（MQL5）

試行データ（シンボル・パラメータ・結果）は**外部 DB（SQLite）に集約**し、選定・検証はすべて DB 照会で行う（フラットファイルの `.set`/`.csv` は採用しない）。

**書込みパターン（テスター制約への対応）**
- MT5 のテストエージェントはサンドボックス化・ネットワーク遮断され、並列実行されるため、各エージェントから直接 DB 書込みはしない。
- **各パス（エージェント）`OnTester()`**: 要件 #11 の指標を計算し、`FrameAdd` でパラメータ＋各指標を送出。
  - **Y1: 「的中率」は MT5 標準統計に無いため EA 内で自前集計する。** 各確定足で `fc.signalDir` と次足の実現方向を突き合わせてカウントし、`OnTester` で的中率として確定する。期待値・シャープ・最大DD は `TesterStatistics()` から取得可能。
- **`OnTesterPass()`（ターミナル側＝単一プロセス）**: フレームを `FrameNext` で受信し、`MarkovDB.mqh` 経由で **1 か所から `trials` テーブルへ INSERT**。これで通信制約とロック競合の双方を回避する。
- **`OnTesterDeinit()`（ターミナル側）**: 当該 run のサマリ（best 行）を確定（任意。選定はクエリでも可）。

**複合スコア（R2 反映：正規化してから合成）**
- 各指標を**当該 run（同一シンボル・同一最適化）内で正規化**してからスコア化し、単位差による偏りを除く：
  ```
  nSharpe = minmax(Sharpe)          # 0..1
  nPayoff = minmax(ExpPayoff)       # 0..1
  nMaxDD  = minmax(MaxDD%)          # 0..1（大きいほど悪い）
  score   = wS*nSharpe + wP*nPayoff − wD*nMaxDD     # 重みは input
  ```
- 正規化は DB 側でも `SELECT` 時に算出可能（per-symbol の min/max を副問い合わせ）。EA 側では生指標のみ記録し、**スコアは DB クエリで一元計算**する方式を既定とする（記録の単純化・再計算容易性）。

**選定（DB クエリでシンボル別ベスト）**
- 例（シンボルごとにスコア最大の試行）:
  ```sql
  SELECT t.* FROM trials t
  JOIN (SELECT symbol, MAX(score) AS s FROM v_scored GROUP BY symbol) b
    ON t.symbol=b.symbol
  WHERE t.id IN (SELECT id FROM v_scored WHERE score=b.s);
  ```
  （`v_scored` は正規化スコアを算出するビュー）

### 14.2 ② オーケストレーション層：シンボル連続最適化（MT5 外ランナー）
- 入力: シンボルリスト（例 `EURUSD,USDJPY,GBPUSD,AUDUSD,…`）、期間、最適化レンジ。
- 各シンボルについて**テスター設定 `.ini`** を生成し、`terminal64.exe /config:<symbol>.ini /portable` で起動。
  - `.ini` の `[Tester]` セクション例: `Expert`, `Symbol`, `Period`, `Optimization=2`（遺伝的）, `FromDate/ToDate`, 入力レンジ（`.set`）, `ShutdownTerminal=1`。
- 1 シンボルの最適化完了（端末終了）を待って次シンボルを起動するループ。
- 実装は OS バッチ or Python ランナー（`subprocess` で逐次起動）。**ユーザー操作はランナー 1 回起動のみ**。

### 14.3 ③ ポートフォリオ検証 EA：全シンボル一括バックテスト（MQL5）
- `MarkovPortfolioEA.mq5` は `OnInit` で **SQLite DB に接続し、シンボル別ベスト param を `SELECT` で読み込む**（14.1 の選定クエリ）。
- 1 パスで**全対象シンボルを同時に実行**。各シンボル独立のエンジン／ポジション／モデルを内部配列で保持（ペア別＝要件 #5 を維持）。
- 自シンボル以外のデータは `CopyRates(symbol,…)` で取得（ブローカーに履歴がある前提）。
- 出力: シンボル別＋ポートフォリオ合算の成績。**シンボル切替なしで全体成績を確認可能**。

### 14.3a DB スキーマ（SQLite / `MarkovDB.mqh`）
```sql
CREATE TABLE IF NOT EXISTS runs (
  run_id     INTEGER PRIMARY KEY,
  symbol     TEXT,
  tf         TEXT,
  from_date  TEXT,
  to_date    TEXT,
  created_at TEXT
);
CREATE TABLE IF NOT EXISTS trials (
  id          INTEGER PRIMARY KEY,
  run_id      INTEGER REFERENCES runs(run_id),
  symbol      TEXT,
  params_json TEXT,        -- 入力パラメータ一式（JSON）
  ret_window  INTEGER, std_window INTEGER, sigma_thr REAL,  -- 主要 param は列でも保持（クエリ用）
  hit_rate    REAL,        -- 的中率（EA 内で自前集計：Y1）
  exp_payoff  REAL,        -- 期待値
  sharpe      REAL,
  max_dd_pct  REAL,
  net_profit  REAL,
  trades      INTEGER,
  created_at  TEXT
);
-- 正規化スコアのビュー（per-symbol min/max で正規化、重みは外部から）
CREATE VIEW IF NOT EXISTS v_scored AS
SELECT t.*, /* nSharpe, nPayoff, nMaxDD を per-symbol min/max で算出した score */ 0.0 AS score
FROM trials t;
```
- `params_json` で任意パラメータを保持しつつ、頻用 param は列にも持ち最適化・絞り込みを容易にする。
- ③ は `runs`/`trials`/`v_scored` を参照してシンボル別ベストを取得する。
