# 詳細設計書（ドラフト）
## マルコフ連鎖 FX 予測システム（MT5 / MQL5）

> 本書は `docs/概要要件定義書.md`（確定13項目）を実装可能なレベルへ落とした詳細設計である。MQL5（ビルド 3000 以降の `matrix`/`vector` 型を前提）で実装することを想定する。末尾「第12章 新規決定点」に、詳細設計で初めて顕在化した未確定事項を推奨付きで列挙する。

---

## 第1章 設計方針・前提
- 言語: MQL5。行列演算は標準の `matrix`/`vector` 型を用いる。
- 計算ロジックは共通インクルード `.mqh` に集約し、インジケーターと EA から共有する（要件 #12）。
- 1 インスタンス＝1 シンボル（通貨ペア）を担当し、自シンボルの履歴のみから独立した遷移行列を学習する（要件 #5）。複数ペアは「シンボルごとにインスタンスを動かす」ことで実現する（第10章）。
- すべての判断は**確定足（closed bar）**で行い、未来情報を参照しない（要件: データ漏洩防止）。
- タイムフレームは `input`（既定 PERIOD_D1）。日足境界は MT5 サーバー時刻＝NY クローズ基準（17:00 ET）に整合している前提（要件 #13）。

## 第3章 データ構造（MarkovTypes.mqh）

```mql5
// 市場状態（3 状態：要件 #3）。行列の添字としても使う。
enum ENUM_REGIME { REGIME_BEAR = 0, REGIME_SIDE = 1, REGIME_BULL = 2 };
#define REGIME_COUNT 3

// 1 本の予測結果
struct MarkovForecast
{
   double prob[REGIME_COUNT];   // 各状態の確率（行ベクトル、和=1）
   double diff;                 // P(Bull) - P(Bear)
   int    signalDir;            // +1=Long, -1=Short, 0=中立
   double stickiness[REGIME_COUNT]; // 対角成分（持続性）
};
```
- 遷移行列は `matrix`（3×3）で保持。行 i = 現状態、列 j = 次状態、各行の和 = 1。

## 第4章 共通ライブラリのインターフェース（MarkovEngine.mqh）

```mql5
class CMarkovEngine
{
public:
   // パラメータ注入（input から渡す）
   void Configure(int retWindow, int stdWindow, double sigmaThreshold,
                  int trainLookback, bool expandingWindow, int forecastSteps);

   // 確定足インデックス shift（1=直近確定足）時点で、過去のみを使って予測を生成
   bool BuildForecast(const string symbol, ENUM_TIMEFRAMES tf,
                      int shift, MarkovForecast &out);
};
```
- 内部で Labeler → Matrix → 累乗 → Signal の順に呼ぶ。
- `shift` 起点で過去データのみ参照することで、バー単位のウォークフォワードを自然に満たす。

## 第5章 アルゴリズム詳細（擬似コード）

### 5.1 累積リターンと z スコア（MarkovLabeler）
```
# bar t の状態を決める（t は確定足）
r_t = log(Close[t] / Close[t - retWindow])          # retWindow 本の累積対数リターン
# 直近 stdWindow 本の累積リターン系列 {r} の標準偏差で標準化
sigma = stddev( r[t-stdWindow+1 .. t] )
z_t = (sigma > 0) ? r_t / sigma : 0
```

### 5.2 状態ラベリング
```
if   z_t >= +sigmaThreshold : label = REGIME_BULL
elif z_t <= -sigmaThreshold : label = REGIME_BEAR
else                        : label = REGIME_SIDE
```
- ウォームアップ: 先頭 `retWindow + stdWindow` 本はラベル不能 → スキップ。

### 5.3 遷移行列の構築（MarkovMatrix）
```
N = zero(3,3)
for k in 学習区間の各確定足:
    i = label[k]; j = label[k+1]      # k+1 も確定足のみ
    N[i][j] += 1
# 行正規化（行和で割る）。行和=0 の行は一様分布で埋める（後述ラプラス平滑化も可）
for i in 0..2:
    rowsum = sum(N[i])
    P[i] = (rowsum>0) ? N[i]/rowsum : (1/3,1/3,1/3)
```
- 学習区間は `trainLookback` 本（`expandingWindow=true` なら利用可能な全履歴）。
- ゼロ頻度対策に**ラプラス平滑化（各カウントに +α）**をオプション化（第12章 D-3）。

### 5.4 多ステップ予測（行列累乗）
```
Pn = P^forecastSteps                  # MQL5 matrix の乗算で実装
current = onehot(label[直近確定足])    # 現状態の行ベクトル
probVec = current * Pn                # 予測確率分布
```
- `forecastSteps` は短期（1〜数本）。長期は定常分布に収束しシグナル価値を失う（要件 4.3）。

### 5.5 差分シグナル（MarkovSignal）
```
diff = probVec[BULL] - probVec[BEAR]
if   diff >=  diffThreshold : signalDir = +1   # Long
elif diff <= -diffThreshold : signalDir = -1   # Short
else                        : signalDir = 0    # 中立帯
```

### 5.6 残高%ベースのロット計算（MarkovSizing）
```
# リスク割合を差分強度でスケール（要件 #9）
strength   = clamp(|diff|, 0, 1)
riskFrac   = baseRiskPct + (maxRiskPct - baseRiskPct) * strength   # %→比率
riskAmount = AccountEquity * riskFrac
# 損切り距離 = ATR ベースの動的 SL（D-1 確定）
atr        = iATR(symbol, tf, InpAtrPeriod)[直近確定足]
slDistance = InpAtrSLMult * atr            # 価格距離（例 1.5×ATR）
slValue    = slDistance / TickSize * TickValue   # 1 ロットあたりの損切り金額
lots       = riskAmount / slValue
lots       = NormalizeLots(symbol, lots)   # MinLot/LotStep/MaxLot に丸め
```

## 第7章 インジケーター設計（MarkovRegime.mq5）
- `OnCalculate` で確定足ごとに `CMarkovEngine::BuildForecast` を呼ぶ。
- 表示: 状態色分け（背景/サブウィンドウ）、P(Bull)/P(Bear)/diff のライン、スティッキネス値のラベル。
- 描画のみ。発注は行わない。

## 第8章 EA 設計（MarkovBacktestEA.mq5）
- `OnInit`: input を `CMarkovEngine::Configure` に注入。
- `OnTick`: **新規バー確定検出**（`iTime(_Symbol,InpTimeframe,0)` の変化）時のみ処理。
  ```
  if 新規バー確定:
      engine.BuildForecast(_Symbol, InpTimeframe, 1, fc)   # shift=1=直近確定足
      決済/反転判定（既存ポジションと fc.signalDir を比較）
      if fc.signalDir != 0 and ノーポジ:
          lots = sizing(fc.diff, ...)
          発注（成行 + SL/TP）
  ```
- ストラテジーテスターでの最適化対象は input 群（第6章）。

## 第9章 ウォークフォワード/テスター構成
- バー単位処理が `shift` 起点の過去のみ参照のため、**テスター実行が自然にウォークフォワード**になる（各バーでその時点までの履歴から行列を再計算）。
- 明示的な期間分割最適化（前進検証）は MT5 テスターの「フォワードテスト」機能を併用。
- スプレッド／取引コストはテスター設定（実スプレッド or カスタム）で反映（要件 第9章）。

## 第10章 マルチシンボルの扱い
- 各ペア独立（要件 #5）のため、**1 インスタンス＝1 シンボル**を基本とする。
- 複数ペア検証は (a) シンボルごとに最適化を回す、または (b) 多シンボルループ EA（`BuildForecast` を対象シンボル配列で呼ぶ）で対応。MVP は (a) を既定とする（第12章 D-2）。

## 第11章 エラー処理・境界条件
- 履歴不足（`Bars < retWindow+stdWindow+trainLookback`）時は予測スキップ・発注なし。
- `sigma=0`（無変動）時は z=0 → SIDE。
- 行和 0 の行は一様分布（またはラプラス平滑化）で埋める。
- ロットは `SYMBOL_VOLUME_MIN/STEP/MAX` で正規化、証拠金不足チェック。

## 第12章 新規決定点（詳細設計で顕在化・要確認）
| # | 論点 | 推奨 |
| --- | --- | --- |
| ~~D-1~~（確定） | ロット計算の損切り（SL）基準 | **ATR ベースの動的 SL（SL = `InpAtrSLMult` × ATR(`InpAtrPeriod`)）に確定。** 係数・期間は `input` 化しテスター最適化対象 |
| D-2 | マルチシンボル方式 | まず**シンボル別に最適化（1インスタンス1シンボル）**。多シンボルループは将来 |
| D-3 | ゼロ頻度・希少遷移の平滑化 | **ラプラス平滑化（α=1 程度）を既定有効**にし、学習初期の不安定を緩和 |
| D-4 | 利確（TP）/ 手仕舞いルール | 反対シグナル発生 or N 本経過で手仕舞い。TP は R 倍（SL の定数倍）を推奨 |
| D-5 | エントリー単位 | 確定足ベースで 1 ポジション。ピラミッディングは不可（MVP） |

## 第13章 テスト方針
- `.mqh` 単体: 既知の小データで z スコア・行列・累乗・差分の値を検証（テスト用スクリプトで assert）。
- 行列累乗の検証: 行和=1 の保存、`P^1` が `P` に一致。
- EA 結合: テスターで短期間を実行し、発注が確定足のみ・未来参照なしであることをログで確認。
